# depgraph

Инструмент визуализации графа зависимостей пакетов Alpine Linux (apk).
Практическая работа «Конфигурационное управление», вариант 27.

## 1. Общее описание

Консольное приложение на Python (только стандартная библиотека), которое
строит граф зависимостей пакета. Менеджеры пакетов и сторонние библиотеки
для получения зависимостей не используются.

Состояние проекта: **этап 2** — сбор данных. Приложение скачивает индекс
репозитория Alpine (`APKINDEX.tar.gz`), разбирает его собственным кодом
и выводит прямые зависимости пакета заданной версии.

## 2. Описание функций и настроек

| Параметр | Описание |
|---|---|
| `-p`, `--package NAME` | имя анализируемого пакета (обязательный) |
| `-r`, `--repo URL\|FILE` | URL репозитория или путь к файлу тестового репозитория (обязательный) |
| `-t`, `--test-mode` | считать `--repo` путём к файлу тестового репозитория |
| `-V`, `--pkg-version VERSION` | версия пакета (обязательна для реального репозитория) |
| `-o`, `--output FILE.png` | имя файла с изображением графа (по умолчанию `graph.png`) |
| `-a`, `--ascii-tree` | вывести зависимости в виде ASCII-дерева |
| `-d`, `--max-depth N` | максимальная глубина анализа, целое число от 1 (по умолчанию 3) |
| `-f`, `--filter TEXT` | не учитывать пакеты, в имени которых есть подстрока |
| `--show-params` | напечатать все параметры в формате `ключ=значение` |

Обработка ошибок: недопустимое имя пакета или версии, пустой или неверный
URL, отсутствующий файл тестового репозитория, нечисловая или
неположительная глубина, имя изображения не `.png`, несуществующая папка
для изображения, пробелы в подстроке фильтра, отсутствие версии для
реального репозитория. При ошибке печатается сообщение, код завершения 2.

Как это работает. По `--repo` формируется адрес `<repo>/APKINDEX.tar.gz`,
архив скачивается через `urllib` и читается через `tarfile` (в нём файл
`APKINDEX`). Записи индекса разделены пустой строкой; используются поля
`P` (имя), `V` (версия), `D` (зависимости), `p` (что пакет предоставляет).
Зависимости вида `so:libc.musl-x86_64.so.1` или `cmd:sh` заменяются пакетом,
который их предоставляет (поле `p`), версионные ограничения (`>=1.2`)
отбрасываются, конфликты (`!name`) пропускаются. Зависимость, которой нет
в индексе (например, она в другом репозитории), остаётся в списке под своим
именем. Если версия не найдена, программа покажет доступные версии.

Модули: `config.py` (параметры и проверка), `fetch.py` (загрузка по URL),
`apk.py` (разбор индекса и поиск зависимостей), `cli.py` (запуск),
`main.py` (точка входа).

Коды завершения: 0 — успех, 1 — ошибка данных или сети, 2 — ошибка
параметров.

## 3. Сборка и запуск тестов

Сборка не нужна. Требуется Python 3.8 или новее.

```
run.bat test          # Windows
./run.sh test         # Linux и macOS
python -m unittest discover -s tests -t .
```

## 4. Примеры использования

Если версия неизвестна, укажите любую: программа сообщит доступные.

```
run.bat -p busybox -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 -V 0
Ошибка: пакет busybox версии 0 не найден; в репозитории есть версии: <версия>
```

Прямые зависимости пакета (формат вывода):

```
run.bat -p busybox -r https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 -V <версия>
Прямые зависимости пакета busybox (<версия>):
  musl
  ...
```

Параметры в формате «ключ=значение»: добавьте `--show-params`.

Ошибки параметров (код 2):

```
run.bat -p "bad name" -r x
depgraph: error: argument -p/--package: недопустимое имя пакета 'bad name': ...

run.bat -p nginx -r https://x.org -V 1 -d 0
depgraph: error: argument -d/--max-depth: глубина должна быть не меньше 1, получено 0
```

Ошибки данных (код 1): недоступный сервер, код ответа не 200, повреждённый
архив, пакет или версия не найдены.
